# Test-Driven Development

> 适配自 mattpocock/skills 的 tdd skill，去掉子文件引用，保留核心方法论。

## 哲学

**核心原则**：测试应该通过公共接口验证**行为**，而不是实现细节。代码可以完全改变，测试不应该变。

**好测试**是集成式的：通过公共 API 执行真实代码路径。它们描述系统**做什么**，而不是**怎么做**。好测试读起来像规格说明——"用户能用有效购物车结账"告诉你确切存在什么能力。这种测试能在重构中存活，因为它们不关心内部结构。

**坏测试**耦合到实现。它们 mock 内部协作者、测试私有方法、或通过外部手段验证（比如直接查数据库而不是用接口）。警告信号：当你重构时测试坏了，但行为没变。如果你重命名一个内部函数测试就失败，那些测试测的是实现，不是行为。

## 反模式：水平切片

**不要先写所有测试，再写所有实现。** 这是"水平切片"——把 RED 当成"写所有测试"，GREEN 当成"写所有代码"。

这会产生** crap 测试**：

- 批量写的测试测的是**想象中**的行为，不是**实际**行为
- 你最终测的是东西的**形状**（数据结构、函数签名），而不是用户面对的行为
- 测试对真实变化变得不敏感——行为坏了它们通过，行为没事它们失败
- 你跑在了自己的 headlights 之前，在理解实现之前就承诺了测试结构

**正确做法**：通过 tracer bullet 做垂直切片。一个测试 → 一个实现 → 重复。每个测试回应你从上一个循环学到的东西。因为你刚写过代码，你确切知道什么行为重要、如何验证它。

```
错误（水平）：
  RED:   test1, test2, test3, test4, test5
  GREEN: impl1, impl2, impl3, impl4, impl5

正确（垂直）：
  RED→GREEN: test1→impl1
  RED→GREEN: test2→impl2
  RED→GREEN: test3→impl3
  ...
```

## 工作流

### 1. 规划

探索代码库时，使用项目的领域术语表（`CONTEXT.md`，如果存在），让测试名和接口词汇匹配项目语言，并尊重你触碰区域的 ADR。

写任何代码之前：

- [ ] 与用户确认需要哪些接口变更
- [ ] 与用户确认要测哪些行为（按优先级）
- [ ] 识别深模块机会（小接口，深实现）
- [ ] 为可测试性设计接口
- [ ] 列出要测的行为（不是实现步骤）
- [ ] 获得用户对计划的批准

提问："公共接口应该长什么样？哪些行为最重要需要测试？"

**你无法测试一切。** 与用户确认哪些行为最关键。把测试精力放在关键路径和复杂逻辑上，不是每个可能的边缘情况。

### 2. Tracer Bullet（示踪子弹）

写**一个**测试，确认系统的一**件**事：

```
RED:   为第一个行为写测试 → 测试失败
GREEN: 写最小代码通过 → 测试通过
```

这是你的 tracer bullet——证明端到端路径走通。

### 3. 增量循环

对每个剩余行为：

```
RED:   写下一个测试 → 失败
GREEN: 最小代码通过 → 通过
```

规则：

- 一次一个测试
- 只写够通过当前测试的代码
- 不要预判未来测试
- 测试聚焦于可观察行为

### 4. 重构

所有测试通过后，寻找重构候选：

- [ ] 提取重复
- [ ] 深化模块（把复杂度移到简单接口后面）
- [ ] 在自然处应用 SOLID 原则
- [ ] 考虑新代码揭示的现有代码问题
- [ ] 每步重构后跑测试

**永远不要在 RED 时重构。** 先回到 GREEN。

## 每个循环的检查清单

```
[ ] 测试描述行为，不是实现
[ ] 测试只用公共接口
[ ] 测试能在内部重构中存活
[ ] 代码对这个测试是最小的
[ ] 没有投机性的功能添加
```

## 与本项目的适配说明

- 本项目用 `pytest`（`pyproject.toml` 配置 `asyncio_mode=auto`、`filterwarnings=error`）
- 测试约定：无 `conftest.py`，每个测试文件自带 fixture；内存 SQLite + 真实 ORM；模块级函数；`monkeypatch.setattr` 替换底层函数；`app.dependency_overrides` 替换 service；`@patch` 替换 requests
- 本项目已有 387+ 测试，新功能应延续现有测试风格（参考 `tests/unit/test_qa_orchestration.py`、`test_api_queries.py`）
- 质量门禁：Ruff format + Ruff check + mypy strict + pytest 全过，CI 三项全绿才算完成
- 领域术语见 `CONTEXT.md`（如存在）或 `docs/ROADMAP.md`
