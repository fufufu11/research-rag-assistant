# ADR 0002: P95 延迟验收口径限定为检索阶段

## 状态

Accepted（2026-07-24）

## 背景

阶段 10.3 性能优化的 `docs/ROADMAP.md` 原验收标准为"P95 延迟降低 50%，并发 10 请求无阻塞"，但未明确 P95 的测量范围。

代码探索与延迟构成分析显示，端到端问答延迟的大致分布为：

| 阶段 | 估算耗时 | 占比 |
|---|---|---|
| LLM 生成 | 1-10 秒（流式首字 ~0.5-2 秒） | 80%+ |
| Reranker（Cross-Encoder） | 100-500ms | 5-15% |
| 检索（BM25 建索引 + Qdrant 检索 + RRF 融合） | 50-150ms | 5-10% |
| DB 查询 | 10-50ms | 1-3% |

本阶段优化对象是检索阶段（BM25 索引缓存消除重建开销 + 并发检索重叠 BM25 与 Qdrant）。若 P95 口径为端到端（含 LLM 生成），则无论检索层如何优化，都无法移动端到端 P95 50%——LLM 生成占 80%+，检索仅占 5-10%，即便检索耗时全砍也只降 5-10%。

Reranker（Cross-Encoder）虽属检索后处理，但本阶段不优化它（独立阶段），若计入 P95 会稀释检索优化的可观测效果。

## 决策

P95 验收口径限定为**检索阶段**，即 `QaService._retrieve_hybrid` 的执行耗时（BM25 建索引 + BM25 检索 + Qdrant 检索 + RRF 融合），**不含 LLM 生成与 reranker**。

- 基准脚本 `scripts/benchmark_retrieval.py` 仅计时 `_retrieve_hybrid`，独立计算 P50/P95/P99。
- 验收门槛：优化分支相对 main 基线，检索阶段 P95 降低 ≥ 50%。
- "并发 10 请求无阻塞"作为独立验收项，验证 `ThreadPoolExecutor` 并发检索在多请求下不阻塞。

## 后果

- **正面**：验收可达成（BM25 缓存消除 ~100ms 重建开销 + 并发重叠 ~50ms，检索 P95 降 50% 现实可达）；优化目标聚焦检索层，不被 LLM API 延迟噪声淹没。
- **负面**：不反映用户感知的端到端延迟。用户体感延迟仍由 LLM 生成主导，本阶段优化对端到端 P95 改善有限（~5-10%）。
- **风险**：未来读者可能误解"P95 降 50%"为端到端。本 ADR 显式记录口径，并在 `docs/ROADMAP.md` 10.3 节标注"检索阶段 P95"以避免混淆。
- **未来演进**：若后续优化 LLM 延迟（如流式首字优化、更快模型、KV cache），需另立端到端 P95 验收口径，与本检索阶段口径并存。
